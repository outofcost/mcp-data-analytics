Записал 11 ноября 2026 в 15:30 МСК, до первого прогона. После прогонов файл не меняю. Его sha256 лежит рядом в `protocol.sha256`.

## Вопрос

Задание просит, чтобы ассистент проходил анализ по этапам: загрузка, очистка, графики, выводы. Порядок этапов хранится в сервере: в поле `instructions` и в поле `next_step` каждого ответа инструмента. Зависит ли соблюдение порядка от модели, которая вызывает инструменты?

## Гипотеза

Порядок держится на всех четырёх моделях, включая слабую: сервер подсказывает следующий шаг в каждом ответе, и модели остаётся ему следовать. Качество выводов при этом от модели зависит: слабая модель чаще пропускает заложенные закономерности.

## Метрики

Все метрики считает `score.py` по журналу клиента `console-log.txt`, по тексту ответа `answer.md` и по файлу `meta.json` (время и стоимость). Руками ничего не размечаю. Успешным вызовом называю запись журнала с `is_error: false`.

**Цепочка выдержана.** Главная метрика. Условия взяты из `docs/acceptance.md`, все пять должны выполниться:

1. Прогон закончился ответом модели (статус `ok`: без предела шагов и без сбоя).
2. Первым успешным вызовом идёт `load_data`. Перед ним допускаю `list_data_files`: его разрешают инструкции сервера.
3. Успешный `clean_data` стоит раньше первого успешного графика.
4. Построено не меньше трёх разных графиков. График это успешный вызов `plot_trend`, `plot_distribution` или `correlation_analysis`. Разными считаю вызовы, у которых отличается инструмент или аргументы, кроме `dataset_id`.
5. Есть успешный `save_report`, до него есть успешный `collect_findings`, после последнего `save_report` успешных вызовов нет.

**Отчёт сохранён.** В журнале есть успешный `save_report`.

**Этапы по порядку.** Номера этапов успешных вызовов не убывают: загрузка (`list_data_files`, `load_data`, `describe_data`) → очистка (`clean_data`) → графики (`suggest_charts`, `plot_trend`, `plot_distribution`, `correlation_analysis`) → выводы (`collect_findings`, `save_report`). Необязательный `abc_analysis` в порядке не учитываю.

**Графики.** Число разных графиков по правилу из условия 4.

**Вызовы и ошибки.** Число вызовов инструментов, число вызовов с `is_error: true`, число исправленных ошибок. Ошибку считаю исправленной, если позже в том же прогоне есть успешный вызов того же инструмента.

**Закономерности.** Только для `sales_data.csv`. Текст для проверки: `answer.md` плюс аргументы `conclusions` и `recommendations` последнего успешного `save_report`. Текст делю на строки, регистр не учитываю. Закономерность названа, если есть строка, где:

- сезонность: встречается «декабр»;
- рост Казани: встречается «казан» и одно из «рост», «раст», «вырос», «прирост», «увелич», «быстр»;
- убыток «Готовых обедов»: встречаются «готов» и «обед» и одно из «убыт», «отрицательн», «минус».

Вывод прогона осмысленный, если названы две закономерности из трёх: это критерий из `docs/acceptance.md`.

**Стоимость и время.** Стоимость из поля `usage.cost` ответа OpenRouter, сумма по прогону. Время от запуска до конца прогона, по часам скрипта.

## Как решаю

Для каждой модели отдельно, по 6 прогонам (3 на файл):

- цепочка выдержана в 5 или 6 прогонах из 6: **порядок держится**;
- в 3 или меньше: **порядок не держится**;
- в 4 из 6: **не решено**, вывода по модели нет.

Для каждой модели по 3 прогонам на `sales_data.csv`:

- осмысленный вывод в 2 или 3 прогонах из 3: **выводы осмысленные**;
- иначе: **выводы слабые**.

Общий вывод:

- порядок держится на всех четырёх моделях: первая часть гипотезы подтверждена;
- держится на трёх и не держится на `mistralai/mistral-nemo`: порядок зависит от модели, серверной подсказки слабой модели не хватает. Пишу это как есть;
- любой другой расклад: гипотеза не подтверждена, расклад привожу в таблице.

Вторая часть гипотезы подтверждена, если у `mistralai/mistral-nemo` выводы слабые, а у остальных трёх осмысленные. Иначе пишу, что различия в качестве выводов эксперимент не показал.

## Что делаю при сбоях

- Сбой API провайдера (ошибка сети, отказ провайдера, пустой ответ) это сбой инфраструктуры. Такой прогон повторяю один раз под тем же номером с пометкой `retry`, оба журнала сохраняю. Если повтор тоже сорвался, прогон считается невыдержанным.
- Предел шагов и остановка модели без отчёта это результат модели. Такие прогоны не повторяю.
- Общий лимит: 30 запусков вместе с техническим и повторами, расход не больше 1 доллара. Скрипт останавливается, когда расход подходит к лимиту. Несделанные прогоны называю в итогах.

## Ограничения

- По 3 прогона на ячейку. Это проверка «держится или нет», долю сбоев модели по ней не оценить.
- Закономерности ищу по ключевым словам. Правило пропустит вывод, сказанный другими словами, и засчитает строку, где слова стоят рядом случайно.
- Закономерности заложены только в один файл. На `orders_dirty.xlsx` проверяю только порядок.
- `collect_findings` отдаёт модели готовые цифры по сезонности, росту и убытку. Метрика показывает, донесла ли модель их до вывода. Умение найти закономерность в сырых данных она не проверяет.
- Один запрос, один клиент, один день. Модели OpenRouter обслуживают разные провайдеры, от запуска к запуску провайдер может меняться.
- Сервер зафиксирован на коммите `08f2341`. Поздние версии сервера эксперимент не проверяет.
