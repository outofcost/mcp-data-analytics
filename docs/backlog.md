# Что осталось нереализованным и как я бы это доделал

Задание просит подробно описать, что не сделано и как это доделать. Здесь девять пунктов по убыванию пользы. По каждому написано, что есть сейчас, чем это грозит, какой ход я бы сделал и сколько это займёт. Часы это моя оценка для одного человека, без запаса на ревью. Сумма около 36 часов.

Факты проверены по коду на 11 ноября 2026. Известные ограничения без плана работ собраны отдельно, в [limitations.md](limitations.md).

## 1. Закрыть открытые входы: вход и квоты

Сейчас у адреса сервера по HTTP нет авторизации: любой, кто знает адрес, вызывает инструменты. Бот отвечает всем, список разрешённых чатов пуст. Каждый анализ через бота тратит мой баланс у провайдера модели, около 0,003 доллара за запуск по журналам в `examples/`, и предела на пользователя нет.

Это главный риск открытого демо: сервер можно загрузить запросами, а баланс потратить.

Доделал бы в три шага. Первый: проверка токена на сервере, в SDK для этого есть параметр `token_verifier`, клиент передаёт токен в заголовке. Второй: в боте счётчик анализов на чат за сутки, хранится в файле рядом с загрузками. Третий: предел расходов на ключ в кабинете провайдера, это делается без кода.

Оценка: 6 часов. Работу токена с коннектором claude.ai я не проверял, она может потребовать OAuth и удвоить оценку.

## 2. Отделить данные одного пользователя от данных другого

Сейчас у таблиц и файлов нет владельца. По HTTP память у всех клиентов общая: таблицу защищает только случайный хвост в её имени. Файлы, присланные боту, лежат в `data/uploads/` и не удаляются. Отчёты в `output/` тоже остаются навсегда.

Чужую таблицу нельзя угадать, но её можно прочитать, если узнать имя. Диск сервера со временем заполнится.

Доделал бы так: у каждой таблицы появляется владелец (чат в боте, токен из пункта 1 по HTTP), инструменты отдают таблицу только владельцу. Загрузки и отчёты ложатся в папку владельца и удаляются по возрасту, например через сутки. Число таблиц на владельца ограничено.

Оценка: 5 часов, после пункта 1.

## 3. Сверять числа в выводах модели с расчётами сервера

Сейчас `save_report` проверяет форму вывода: длину фразы и то, что в пояснении есть хотя бы одна цифра. Истинность числа он не проверяет. Модель может написать число, которого нет в ответе `collect_findings`, и оно попадёт в отчёт.

На моих прогонах числа совпадали, но это наблюдение, проверки в коде нет.

Доделал бы так: сервер достаёт числа из каждого пояснения и ищет их среди чисел `collect_findings` и фактов под графиками, с допуском на округление. Число без источника возвращается модели в списке нарушений, тем же путём, что и ошибки формы. Производные числа (сумма двух долей) модель должна будет заменить на исходные.

Оценка: 4 часа.

## 4. Дать ответить на уточняющий вопрос

Сейчас сервер умеет спросить, но не умеет услышать ответ. `load_data` возвращает вопросы в поле `questions`: например, когда даты читаются и как «день/месяц», и как «месяц/день». Аргумента, которым пользователь выбрал бы порядок, у `load_data` нет. Бот между сообщениями помнит только последний файл.

Из-за этого спорный файл читается по умолчанию, а пользователю остаётся пересохранить его в другом виде.

Доделал бы так: аргументы `date_order` и `decimal_mark` в `load_data` со значением «определить самому» по умолчанию. В боте: вопрос сервера уходит пользователю отдельным сообщением, его ответ передаётся модели вместе с тем же файлом.

Оценка: 4 часа.

## 5. Убрать четыре известных искажения в расчётах

Их нашло внешнее ревью кода, я их подтвердил и не успел исправить.

- Сезонность на редких данных. Месяц без единой строки считается как месяц с нулём продаж. На таблице с пропусками в датах сервер покажет сезонный провал, которого нет.
- Одиночное крупное значение. Правило выбросов исключает из расчётов редкое значение, стоящее особняком. Так выглядит опечатка с лишним нулём, но так же выглядит и одна настоящая крупная сделка. Сервер сообщает об исключении и позволяет вернуть строку, но по умолчанию её не считает.
- Пропуски, заполненные медианой, входят в общий итог. Сумма по колонке включает значения, которых в данных не было.
- Числа вида `1,234` читаются как 1,234, хотя в американской записи это 1234. Вопроса пользователю сервер при этом не задаёт.

Доделал бы так. Сезонность считать по месяцам, где есть строки, и требовать минимум строк на месяц. Спорный выброс не исключать молча, а возвращать вопросом (нужен пункт 4). В итогах показывать сумму без заполненных значений и рядом число заполненных. Запись числа определять по всей колонке: если после запятой везде ровно три цифры, задавать вопрос.

Оценка: 5 часов, по часу с тестом на каждое и час на прогон тестовых файлов.

## 6. Хранить таблицы на диске

Сейчас таблицы живут в памяти процесса. После перезапуска сервера файл надо загружать заново, нумерация таблиц начинается с единицы, локально новый отчёт перезаписывает старый в той же папке.

Доделал бы так: таблица и состояние анализа сохраняются в папку кэша по `dataset_id`, сервер поднимает их при обращении. Интерфейс инструментов не меняется.

Оценка: 3 часа.

## 7. Различать «модель ответила» и «модель ничего не сделала»

Сейчас сервер направляет модель только после первого вызова инструмента: порядок приходит в ответах. На сравнении моделей слабая модель не сделала ни одного вызова и ответила текстом. Консольный клиент записал такому запуску статус `ok`, хотя анализа не было.

Доделал бы так: клиент ставит отдельный статус, если модель завершила разговор без единого вызова, и один раз повторяет запрос с прямым указанием начать с `load_data`. В README появляется список моделей, прошедших цепочку.

Оценка: 2 часа.

## 8. Сделать навык для помощника поверх сервера

Сейчас файл, прикреплённый к чату Claude без упоминания сервера, Claude разбирает своими средствами, и сервер не вызывается. Помогает только слово «analytics» в запросе.

Доделал бы так: короткий навык с правилом «таблицы анализируй через сервер analytics и следуй полю next_step». В SDK есть расширение, которое отдаёт такие навыки клиенту как ресурсы сервера. Я видел его в документации и не пробовал.

Оценка: 3 часа, из них половина на проверку в claude.ai и Claude Desktop.

## 9. Пройти проверки, которых не было

- Установка на чужой машине человеком без контекста: я ставил проект сам в чистое окружение.
- ChatGPT с этим сервером: подключался только пробный сервер с одним инструментом, график он не показал.

Оценка: 4 часа.
