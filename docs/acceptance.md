## Как проверяю, что выводы осмысленные

Данные генерирую сам, поэтому знаю правильный ответ. В `data/sales_data.csv` закладываю три закономерности, генератор с фиксированным зерном лежит рядом с данными:

1. Сезонность: в декабре продажи заметно выше, чем в среднем месяце.
2. Один регион растёт быстрее остальных.
3. Один товар продаётся в убыток.

Вывод считаю осмысленным, если отчёт назвал две закономерности из трёх. Одну или ни одной: критерий «Работоспособность» не выполнен.

## Как проверяю порядок шагов

Порядок этапов хранится в сервере. Цепочку считаю выдержанной, если в журнале вызовов:

- первым идёт `load_data`;
- `clean_data` вызван раньше первого графика;
- построено три графика или больше;
- `save_report` идёт последним и после `collect_findings`.

Ту же цепочку прогоняю на нескольких моделях через API. Правило решения для этого сравнения записываю отдельным протоколом до прогонов.

## Что проверяю руками и что автоматически

- Автоматически: инструменты и ошибки (`pytest`), стиль кода (`flake8`), порядок вызовов по журналу.
- Руками: диалог в готовом чате, вид графиков, текст отчёта, подключение по README на втором аккаунте.

Всё, что проверить не успел, перечисляю в README в разделе с ограничениями.

## Где я отступил от записанного

- Единицы на осях. Я записал «подписи осей с единицами». Валюту сервер больше не подписывает: по имени колонки `Sales` не узнать, рубли в файле или доллары. На оси остаются масштаб («тыс.», «млн») и «шт.» у количества, валюта появляется только из имени колонки.
- Сравнение моделей. Гипотеза «порядок держится на всех моделях» не подтвердилась: слабая модель не вызвала ни одного инструмента. Одна модель из четырёх не измерена из-за отказов провайдера.
- Проверка документации. Критерий требует, чтобы сервер по README подключил кто-то без контекста. Такой проверки не было.
